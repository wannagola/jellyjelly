젤리젤리

먹은 젤리를 하나씩 병에 담아 모으는 기록 앱. 북적북적이 책을 쌓아 올리듯, 젤리를 쌓아 올린다.

2026.09.11 전제 · 혼자 쓰는 앱 · 내 전용 서버 · 비상업 상태 · 착수 가능
요약

전제가 바뀌면서 달라진 것

"배포용"을 전제로 썼던 1판의 제약 대부분이 사라졌습니다. 범위가 절반 이하로 줄었습니다.

사진 저작권 문제 소멸 — 아무 이미지나 가져다 쓰세요 배포하지 않고 내 기기에만 두는 개인적 이용이라, 1판에서 제일 크게 걱정했던 부분이 통째로 없어졌습니다. 쿠팡·네이버에서 상품 이미지를 길게 눌러 저장하거나 URL을 붙여넣으면 끝. 자동 누끼는 필수 기능에서 "있으면 좋은 것"으로 내려갑니다.
데이터 씨드 200종 → 0종에서 시작 내가 먹는 젤리만 들어가면 되므로, 미리 도감을 채울 이유가 없습니다. 먹을 때마다 하나씩 추가되고, 그게 곧 내 도감이 됩니다. 1판에서 "제일 지루하지만 제일 중요하다"고 했던 작업이 사라졌습니다.
공공 API 식약처 API 신청도 당장은 불필요 칼로리·원재료는 봉지 뒷면을 보고 적거나, 아예 안 적어도 됩니다. 나중에 "성분 자동으로 채워지면 좋겠다" 싶을 때 붙이면 되는 선택 사항으로 내려갑니다.
일정 2주+ → 4~5일 소셜·추천 알고리즘·크롤러·씨드 구축이 전부 빠졌습니다. 내 계정 하나짜리 서버를 붙이는 데 반나절쯤 더 듭니다.
저장 내 전용 서버를 두기로 — 저장 문제 해결 Supabase에 내 계정 하나만 만들고 잠급니다. 폰을 바꿔도, 앱을 안 열어도, 사진이 몇 장이든 기록이 안전합니다. 다만 저작권은 서버와 무관합니다 — 로컬이든 내 서버든 원래 문제가 없었고, 대신 "진짜 로그인을 걸어야 한다"는 조건이 하나 붙습니다. 3절을 보세요.
01

사진은 이렇게 넣습니다

세 경로를 다 열어두고, 어느 쪽으로 들어와도 같은 모양의 젤리 스티커가 되게 만듭니다.

  • 이미지 URL 붙여넣기 — 쇼핑몰 상품 사진 주소를 복사해 붙이면 앱이 받아서 기기에 저장합니다. 원본 링크가 죽어도 내 사진은 남습니다. 가장 빠르고, 원하시던 "상품 디스플레이 느낌"이 그대로 나옵니다.
  • 사진 앨범에서 고르기 — 이미 폰에 저장해 둔 이미지를 그대로.
  • 직접 촬영 — 봉지를 찍는 것 자체가 기록의 순간이 되는 경로. 여행지·직구 젤리는 이 방법뿐입니다.
  • 사진이 없어도 예쁘게 — 등록 직후엔 고른 색 + 모양(곰·벌레·링·큐브·하트)으로 만든 젤리 SVG가 자동 배정됩니다. 사진은 나중에 채워도 되고, 안 채워도 빈 카드가 안 생깁니다.
  • 누끼는 선택 기능 — 원할 때만 버튼 한 번으로. 브라우저 안에서 처리(@imgly/background-removal)되니 사진이 밖으로 나가지 않습니다. 없어도 앱은 완성됩니다.
02

젤리 정보는 어떻게 채우나

"검색하면 젤리 정보가 뜬다"를 포기하고, "한 번 적으면 다시는 안 적어도 된다"로 바꿉니다. 혼자 쓰는 앱에서는 이쪽이 훨씬 낫습니다.

기본
처음 먹는 젤리는 이름만 적으면 끝 이름(필수) 외엔 전부 나중에 채워도 되는 선택 항목. 브랜드·색·모양은 고르기 쉬운 칩으로, 성분은 비워둬도 됩니다. 등록이 10초를 넘으면 앱을 안 쓰게 됩니다.
두번째
부터
이미 먹어본 젤리는 검색해서 한 번 탭 내 도감이 쌓일수록 등록이 빨라집니다. 초성 검색(ㅁㄱㅁ → 마이구미)을 넣으면 체감이 확 달라집니다.
선택
나중에 생각나면 붙이는 것들 식약처 품목제조보고 API로 제조사·원재료 자동 채우기, 영양성분DB로 칼로리 붙이기, 바코드 스캔. 셋 다 무료지만 지금 할 필요는 없습니다. 조사 결과는 부록에 남겨뒀습니다.
03

어디에 두고 어떻게 여나

"내 전용 서버"로 방향을 잡았습니다. 저장 문제는 이걸로 끝납니다.

먼저 짚을 것 — 저작권은 서버와 무관합니다. 로컬에 두든 내 전용 서버에 두든 똑같이 문제가 없습니다. 선을 만드는 건 저장 위치가 아니라 남이 볼 수 있느냐입니다. 그래서 서버를 두면 조건이 하나 새로 붙습니다 — 진짜 로그인을 걸어야 합니다. "URL을 아무한테도 안 알려주면 되지"는 안 됩니다. 주소가 새거나 검색엔진에 잡히는 순간 성립하지 않으니까요.

Supabase를 권합니다

로그인 · DB · 파일 저장 · 접근 제어(RLS)가 한 세트로 무료입니다. 다른 걸 조립할 이유가 없습니다.

항목무료 한도내 앱 기준
파일 저장1 GB640px WebP 기준 장당 약 50KB → 사진 약 2만 장. 평생 안 찹니다
DB500 MB젤리 기록은 한 건에 1KB 미만. 사실상 무제한
전송량5 GB / 월혼자 쓰면 근처도 안 갑니다
로그인내장내 계정 하나만 만들고, RLS로 그 계정만 읽고 쓰게 잠급니다
7일 미사용 시 일시정지무료 플랜 정책매일 쓰면 무관. 긴 여행 뒤엔 대시보드에서 재개 한 번. 귀찮으면 하루 한 번 찔러주는 cron으로 막습니다
자동 백업 없음무료 플랜 정책그래서 내보내기 기능은 그대로 유지합니다. 4절 참고

Firebase는 뺐습니다 — 2026년 2월 3일부터 Storage를 쓰려면 카드 등록(Blaze)이 필수가 됐습니다. 실제 요금은 0원에 머물 가능성이 높지만, 혼자 쓰는 젤리 앱에 카드를 걸어두고 싶진 않을 겁니다. Cloudflare D1+R2도 좋은데 로그인을 직접 붙여야 해서 손이 더 갑니다.

단, 서버 온리로는 만들지 마세요

기록은 일단 기기에 쓰고(IndexedDB), 그 다음 서버로 밀어 올립니다. 이유는 넷입니다 — 지하철에서 인터넷이 끊겨도 기록이 되고, 버튼을 누른 즉시 젤리가 병에 떨어지고(서버 응답을 기다리지 않음), 서버가 잠들어 있어도 앱이 멀쩡히 돌고, Supabase가 언젠가 사라져도 내 기록은 폰에 남습니다. 기기가 하나라 동기화 충돌은 거의 생기지 않아서, updatedAt 비교로 늦은 쪽이 이기게만 해두면 충분합니다.

04

그래도 백업은 남겨둡니다

서버가 생기면서 기기 관련 리스크는 전부 사라졌습니다. 남은 건 하나뿐입니다.

기존 리스크지금
Safari 7일 미사용 시 저장소 삭제해소 서버가 진본. 지워져도 다시 받아옵니다 (그래도 홈 화면 추가는 하세요 — 앱처럼 열려야 매일 씁니다)
기기 저장소 용량 한계해소 사진은 서버에, 기기엔 캐시만. 압축(640px WebP)은 계속 하는 게 좋습니다 — 로딩이 빨라집니다
폰 교체 · 초기화해소 로그인하면 그대로 복구됩니다. 아이패드·맥에서도 열립니다
서비스가 사라지거나 계정이 잠기는 것남음 무료 플랜은 자동 백업이 없습니다. 기록+사진을 zip 하나로 내보내는 기능은 그대로 MVP에 둡니다. 한 달에 한 번이면 충분합니다

그리고 처음부터 남의 이메일로 가입 링크가 열리지 않게 막아두세요. Supabase에서 회원가입을 꺼두고 내 계정만 수동으로 만들면 끝입니다. 이게 "나만 쓰는 서버"를 실제로 성립시키는 한 줄입니다.

06

화면 구조

하단 탭 3개 + 중앙 기록 버튼. 혼자 쓰는 앱에 탭 5개는 과합니다.

🫙
보관함홈. 젤리가 쌓인 병. 달마다 병이 하나씩
🍬
기록하기중앙 버튼. 검색 → 선택 → 별점 → 완료
📅
달력이번 달 먹은 기록. 날짜별 미니 젤리
📖
도감내가 모은 젤리 전체 + 검색. 상세로 가는 입구

"완료" 한 순간에 예산을 몰아주세요

다 먹고 완료를 누르면 젤리가 위에서 떨어져 병 안에 툭 하고 자리를 잡습니다. 스프링 애니메이션 + 살짝 튕김 + 진동 한 번. 이 앱을 매일 열게 만드는 건 기능이 아니라 이 2초입니다. 나머지 화면은 담백해도 괜찮습니다.

  • UI 컴포넌트 라이브러리(MUI·shadcn) — 이 앱의 전부가 커스텀 귀여움인데, 기성 컴포넌트를 쓰면 그 순간 "흔한 앱"이 됩니다. 버튼 몇 개는 직접 만듭니다
  • ORM(Prisma·Drizzle) — 테이블 3개에 쿼리 열 개 남짓. Supabase 클라이언트로 충분합니다
  • 테스트 프레임워크 — 혼자 쓰고 매일 여는 앱이라 버그가 즉시 드러납니다. 나중에 동기화 로직이 복잡해지면 그때 Vitest

진행 순서

각 단계 끝에 손에 잡히는 게 나오게 끊었습니다. 1일차 끝에 이미 폰에서 열립니다.

DAY 1
뼈대 + 젤리 그래픽 프로젝트 세팅, 색 팔레트와 폰트, 젤리 모양 SVG 세트(곰·벌레·링·큐브·하트), 유리병 그래픽. 빈 앱이지만 폰 홈 화면에 올려서 확인합니다.
DAY 2
등록 → 기록 → 보관함 젤리 추가(사진 3경로 포함), 먹는 중 → 완료, 병에 쌓이기. 여기까지면 이미 매일 쓸 수 있습니다.
DAY 2.5 · 반나절
Supabase 붙이기 내 계정 하나 만들고 회원가입 잠그기, 테이블 3개와 RLS, 사진 업로드 경로, 기기→서버 동기화 레이어. 여기까지 오면 폰을 잃어버려도 괜찮습니다.
DAY 3
완료 애니메이션 · 리뷰 · 상세 앱의 인상을 결정하는 2초를 여기서 만듭니다. 별점과 식감 슬라이더, 젤리별 기록 타임라인.
DAY 4
달력 · 검색 · 백업 내보내기 기록이 쌓인 뒤에야 의미가 생기는 화면들. 서버가 있어도 내보내기는 넣습니다 — 무료 플랜엔 백업이 없습니다.
그 다음
도감 · 월간 리포트 · 위시리스트 · 추천 실제로 쓰면서 아쉬운 순서대로. 미리 정하지 말고 써 보고 정하세요.

Q1
기록의 단위는 '젤리 한 봉지'인가요, '먹은 순간'인가요?봉지 단위면 "개봉 → 며칠에 걸쳐 먹음 → 완료"가 자연스럽고, 순간 단위면 달력이 훨씬 촘촘해집니다. 말씀하신 흐름상 봉지 단위로 가정했습니다.
Q2
병은 무엇을 기준으로 나눌까요?달마다(1월 병, 2월 병)를 기본으로 잡았습니다. 브랜드별·맛별·"그냥 하나의 큰 병에 계속 쌓기"도 가능합니다. 하나의 큰 병은 "이만큼 모았다"는 감동이 제일 크지만 개수가 많아지면 느려집니다.

앱 이름작업명은 젤리젤리입니다. 다른 후보: 젤리서랍 · 쫀득쫀득 · 젤리도감 · 구미상자.
